# 行动优先级计划（2026-11）

> 来源：2026-11-11 用户口述的 6 条产品级想法 + 2026-11-13 新增 8 项产品/体验需求（N8–N15）+ 2026-11-14 `/gui-verify` 全功能模拟测试发现的 9 项缺陷与体验问题（G14–G22）+ `docs/ROADMAP.md` 的遗留项。
> 状态：N1–N13 / N15、G14–G22 全功能实测缺陷收口批与 **N14 全站 UI 设计语言整体重构** 均已全部落地并完成 `/gui-verify` 界面验证与全量单元测试（202 lint/test 全绿）。2026-11-14 正式发布 **`2.0` 正式版**，终结 `fork.X` 历史命名，后续版本按 `2.1`、`2.2` 演进。本文档完整保留研发全流程记录。

## 一、产品需求正式编号

### 第一批（2026-11-11，N1–N7）

| 编号 | 想法 | 一句话 |
| --- | --- | --- |
| N1 | 多彩配色 | 不再只用一个主题色撑所有强调色，按元素/语义上多色 |
| N2 | 统一实体表 | 网站等同应用实体，一张"屏幕使用时间"总表；另有开关「网站并入浏览器」 |
| N3 | 卡片重做 | 现在所有页面卡片是灰块，重做样式/层次/质感 |
| N4 | 过渡动效 | Material 早期风格克制的淡入淡出，性能优先 |
| N5 | 分类页重做 | 加「分类 / 应用」视图切换，应用视图里可快速打标签 |
| N6 | 子母程序合并 | 自动判定 + 设置页「子母程序合并」管理，把衍生项并入母程序 |
| N7 | 分类页信息密度 | 扁卡片 + 时长/占比展示 + 紧凑/卡片视图切换 + 排序菜单 |

### 第二批（2026-11-13 新增，N8–N15）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| N8 | 应用与网站共享分类标签 | 其他页面已不再区分应用和网站，分类页同步改为应用与网站共享同一套分类标签 |
| N9 | 预设常用分类标签 | 内置一批常用的默认分类标签，免去用户从零逐个创建 |
| N10 | SVG 分类图标库 | 使用 SVG 绘制一套风格统一的分类图标供自由选择，并替换原有的 Emoji 图标选项 |
| N11 | 典型网站/应用自动归类规则 | 新建一套覆盖大众常用对象的匹配规则（如 `bilibili.com` → 娱乐、`chatgpt.com` → AI、`Word` → 办公），自动把应用/网站归入对应分类 |
| N12 | 设置页全面重构与归类重整 | ① 修复顶部有分类标签却仍能一口气滚到底导致标签无意义的问题，改为按标签分页/独立切换；逐项排查原 Taix 遗留设置（如更新通道、版本显示等），清理并对齐到当前进度。<br>② 重新设计设置大类划分，重新梳理每个设置项的归属。 |
| N13 | 应用内平滑滚动 | 为应用内滚动区域增加平滑滚动效果，消除鼠标滚轮滑动时「一跳一跳」的生硬感 |
| N14 | 全站 UI 设计语言重做 | 将来整体重做 UI 设计（卡片设计、圆角、材质、Dock 栏样式、字体、配色等），彻底摆脱原项目的旧设计语言 |
| N15 | 永久数据记录 + 导入导出 + WebDAV 云同步 | ① 删除设置中「使用时间记录范围（最大一年）」选项，默认永久保留全部使用记录。<br>② 支持数据自由导入与导出（推荐采用 SQLite 一致性快照单文件 / 带校验归档，高效且零解析歧义）。<br>③ 新增 WebDAV 云同步能力。 |

### 第三批（2026-11-14 `/gui-verify` 全功能实测缺陷与体验改进，G14–G22）

| 编号 | 级别 | 模块 | 问题概述与改进方向 |

| G15 | P1 | 统计页 (`ChartPage`) | 堆叠柱图固定 `Height="310"`，周/年视图底部多行图例纵向裁切；改为自适应高度或预留图例安全区 |

| G17 | P1 | 详细页 (`HeatGrid`) | 年视图 12 行（`1月`–`12月`）行高过密导致纵轴标签相互挤压重叠；增设最小行高/行距或滚动自适应策略 |

| G21 | P2 | 分类实体页 & 图标缓存 (`CategoryPage` / `Imager`) | 「应用与网站」部分实体渲染为蓝底占位图，且 `WebFavicons` 解码报错 `NullReferenceException` 降级日志噪音；统一实体图标回退与域名首字母色块复用 |
| G22 | P2 | 设置页 & 搜索浮层细节 (`SettingPage` / `MainWindow`) | ① 新建合并组选满 2 项后红字错误未即时清除；② WebDAV 自动同步 `Toggle` 默认显示英文 `"Off"`；③ `Ctrl+K` 底栏按键徽章与提示文本重复 |

### 第四批（2026-11-19 用户实测反馈，N16–N21 & G23–G28）

#### A. 缺陷与交互问题（G23–G28）

| 编号 | 级别 | 模块 | 问题概述与改进方向 |
| --- | --- | --- | --- |
| G23 | P1 | 全站柱状图 (`ChartPage` / `IndexPage` 等) | 悬停多分类柱子时，底部图例折行向上挤压柱图空间，导致柱体脱离指针反复触发悬停/退出循环、画面一闪一闪；需统一固定绘图区高度或外扩容器，避免图例折行反噬绘图区 |
| G24 | P1 | 设置页 (`SettingPage`) | 设置页内所有条目栏在鼠标经过时出现忽闪现象；需排查条目 `:pointerover` 样式/动画/子控件命中边界 |
| G25 | P1 | 分类页 (`CategoryPage`) | 底部「空分类 (1)」折叠栏在鼠标经过/悬停/点击/按住时变成深灰色；需修正其背景与交互态令牌 |
| G26 | P1 | 分类详情二级页 (`CategoryAppListPage` 等) | 左上角面包屑「应用分类 > 社交」中点击「应用分类」无法返回上一级；需补齐面包屑根项点击返回交互 |
| G27 | P2 | 自绘图表 (`IndexPage` / `DataPage`) | 鼠标点击概览页柱状图或详细页 `ClockRing` 圆环后外围出现蓝色焦点边框；焦点环应仅在键盘导航（`:focus-visible`）时呈现 |
| G28 | P2 | 新建分类弹窗 (`CategoryPage`) | 默认选中的颜色与下方预设色卡不匹配；需按规则自动从色卡中尚未被使用的颜色里挑选默认色 |

## 三、为什么 N2 必须压到最后一块

想法 2 表面是"界面合并显示"，实质是**统计口径换了主语**：从"应用表 + 网站表"变成"一份屏幕时间实体表"。

推导出的连带影响：

- 概览 / 统计 / 详细 / 分类四页各自直连两套接口，全要换数据源；
- 分类体系要能挂在"网站实体"上（现在网站分类是独立一套）；
- 卡片上显示什么字段（网站显示域名还是站点标题？合并实体显示母项还是展开子项？）取决于实体模型；
- 开关「网站并入浏览器」用**浏览器真实活跃时长**，因此开关切换时总额会变，占比之和可能不足 100%，总表需要能容纳"浏览器内其他页面"这个差额项。

先改视觉再换口径，样式要重排两遍。所以顺序是：定模型 → 做合并 → 换口径 → 再动分类页。

## 三·五、N7 · 分类页（"发现页"）信息密度

**问题**：分类页现在是 150×150 的固定方块卡，一张卡只有「图标 + 名称 + 应用数」，
一屏 1440 宽只能放 3–4 个、1080 高只铺两行就到底，下面大片空白。分类一多就要滚动很久，
而每个分类最有用的信息（占用时长、占比、Top 应用）根本没在卡上。

**目标**：同样一屏从 3–4 个提升到 12–20 个，并且每张卡能直接看出「这个分类今天占了多少时间」。

**方案（三步，可独立发布）**

| 步 | 做法 | 数据 | 量级 |
| --- | --- | --- | --- |
| N7-a | 卡片瘦身：150×150 → 宽度自适应、高 96；图标从 40 降到 28，名称 + **时长** + 占比细条；保留应用数做次要信息 | 复用现有分类汇总接口（`api/category/summary` 之类），只取时长 | S |
| N7-b | 视图切换：标题栏加「紧凑 / 卡片」切换（复用 `TabSwitch`），紧凑视图是 4–6 列网格，卡片视图保留现在的方块（但换成新卡片语汇 + 显示时长） | 同上 | M |
| N7-c | 排序与分组：支持按「时长 / 名称 / 应用数」排序；无应用的分类收进折叠区（否则空分类占位） | 本地排序，无需后端 | S |

**不做**：把所有应用平铺进分类页（那是 N5「分类 / 应用」视图的事，等 N6 / N2 的合并实体落地后再做，否则会做两遍）。

**验收线**

1. 1440×900 下首屏至少可见 12 个分类，且无需横向滚动。
2. 每张卡都显示时长；时长为 0 的分类不与有数据混排。
3. 紧凑 / 卡片两种视图切换不丢滚动位置与选中态。
4. 深色与浅色下卡片都是「8px 圆角 + 1px 发丝边 + 零阴影」。

**进度（2026-11-12）**

| 步 | 状态 | 实际做法 |
| --- | --- | --- |
| N7-a | ✅ 已实现，未发版 | 200×92 扁卡片（不用 150 方块）；名字 + 时长同行，应用数在下，底部占比条 + 百分比；目录 / URL 匹配从药丸改成图标右上角小圆点 |
| N7-b | ✅ 已实现，未发版 | 标题栏「紧凑 / 卡片」`TabSwitch`；卡片抽成 `CategoryCard` 控件（应用 / 网站共用），卡片形态靠 `IsCard` 换模板，不换 DataTemplate，滚动位置与选中态不丢；选择走 `[PageState]` |
| N7-c | ✅ 已实现，未发版 | 标题栏「排序」`TabSwitch`（时长 / 名称 / 数量），走 `[PageState]`；三种口径落在 `CategoryCardStats.Sort`：时长（0 时长收尾）、名称（纯字典序）、数量（空分类收尾）；切换只 `Move` 重排，不重拉数据、不重建容器。空分类折叠**未做**（见下） |

**N7-c 的两处口径（2026-11-12）**：

- 排序开关用 `TabSwitch` 而不是下拉菜单：下拉控件 `Select` 只处理 `PointerPressed`、不在 Tab 序列里，
  而分类页在 M3 就已铺过键盘导航；`TabSwitch` 左右键即可切换，样式与「视图」开关同源。
- 「无应用的分类收进折叠区」**没做**：把一列分成「有数据 / 空分类」两套集合后，
  新建、删除、恢复系统分类（会把应用并进去）、重命名这四条路径都要同步两处，
  漏一处就是「新建的分类不显示」；而空分类现在已稳定排在末尾、卡片上不画空进度条、
  时长显示「—」。收益不足以换取这个同步风险，留给 N5「分类 / 应用」视图一起做。

实测 1440 逻辑宽下一行 6 个、纵向约 7 行（≈40 个），远超 12 的目标；只是手头数据只有 6 个分类，所以「≥ 12」是按网格容量算的，不是数出来的。

**排期**：插在视觉体系之后、N6 之前（`fork.8` 发完后作为 `fork.8.5`），因为它是纯展示层改动、不依赖实体模型。

**已拍板的口径（2026-11-12）**：

- 卡片上的时长**只按「今天」算**，本轮**不加周期选择器**（顶部现有 TabSwitch 只是「应用 / 网站」切换）。
- 「408 处硬编码色」这个数字被高估了：实查 `*.axaml` 共 416 处 hex，其中 391 处在 `Theme.axaml`(295) 与
  `Azure.axaml`(96) 里——那是 token 的定义源头（背景光晕渐变 stop、预合成悬停色），不是脏数据。
  散在组件里的只有 25 处 / 13 个文件，已在 `fork.8` 清完。
- `RadiusMedium` 与 `RadiusLarge` 都是 16，语义重复；改动会波及全项目，**与 N7 一起收**，不单独做。
- 列表行进出 stagger 不在 `fork.8`：虚拟化列表复用行容器，容易在滚动时重复触发，单独一批或跟 N7 一起做。

## 五、已拍板的口径（实现时不得违反）

1. **「网站并入浏览器」开关打开时，浏览器时长 = 浏览器真实活跃时长**，不是被追踪网站时长之和。开关切换总额会变，差额是"浏览器内其他页面"，必须在总表里有交代。
2. **子母程序合并后，子进程自动继承母进程的分类**，但**子进程原有标签必须保留**（合并是视图期映射层，不销毁原始归属）。将来拆分子进程，它自动回到原分类。
3. **默认视图是统一实体表**（bilibili 30% / chatgpt 30% / Word 40%），开关只改变网站归属（Chrome 60% / Word 40%），不是两套数据源。

> 来源：对当前 Debug 构建进行全页面、全交互模拟点击与输入验证（覆盖概览、分类汇总、应用/网站详情、统计、详细、分类、设置 5 页签、全局搜索与标题栏）并对照运行日志整理；按严重度分批进入 **`fork.14.5`** 收口。

### P0 · 发版阻断项

1. **G14 · 概览页「今日」加载偶发崩溃导致指标卡与图表空白**
   - **现象与定位**：启动后默认进入概览「今日」时，`ShiJian.Client.ViewModels.IndexPageViewModel.LoadRangeAsync`（`IndexPageViewModel.cs:277`，`appChartData.Skip(FrequentUseNum)...Take(MoreNum).ToList()` 链路）在日志中记录 `System.ArgumentOutOfRangeException`（`IListSkipTakeIterator'1.Fill`），致使顶部时长/应用/站点指标卡、柱状图与榜单空白，切换至「本周」/「自定义」或刷新后恢复。
   - **改进方案**：
     - 对 `IndexPageFrequentUseNum` / `IndexPageMoreNum` 读取及 `Skip`/`Take` 参数增加 `Math.Max(0, ...)` 非负与上界防御，排查并发切换周期/恢复页面状态（`TryRestoreState` + `LoadDataAsync`）时是否存在共享配置未初始化或负值窗口；
     - 在 `LoadRangeAsync` 捕获并展示兜底错误态（复用 `HasEntityError` / `EntityErrorText`），避免静默吞掉非 `HttpRequestException` 异常而把首屏留在空白态；
     - 在 `ShiJian.Tests` 补充边界单测覆盖 `FrequentUseNum <= 0`、`MoreNum <= 0`、空实体列表及并发取消场景。

### P1 · 核心图表排版、搜索与导航一致性

2. **G15 · 统计页（`ChartPage`）柱状图固定高度导致多行图例纵向裁切**
   - **现象与定位**：`Views/ChartPage.axaml:239` 对 `<charts:ColumnChart IsStack="True" Height="310" ... />` 写死总高度 `310`，当「周 / 年」分类图例折行至 3 排时底部图例文字被截断。
   - **改进方案**：
     - 将固定 `Height="310"` 改为 `MinHeight="310"` + `Height="NaN"` 自适应，或把图例容器与绘图柱区高度解耦（柱区固定高度、底部图例 `WrapPanel` 按实际折行撑开容器高度）。

3. **G16 · 分类汇总页（`CategorySummaryPage`）`ColumnChart` 参考线文字重叠**
   - **现象与定位**：`Controls/Charts/ColumnChart.cs:487-494` 分别按固定公式绘制最大值（顶部）、中位线 `midY` 与均值线 `avgY`，当均值接近 50% 最大值或最大值附近时，右侧文本（如 `2h21m` 与 `2h48m`）发生纵向碰撞重叠。
   - **改进方案**：
     - 在 `DrawRefLine` 前收集参考线标签矩形（`Maximum` / `Median` / `Average`），设定最小垂直间距阈值（如 `>= textHeight + 4`），当 `avgY` 与 `midY` 或顶线距离不足时优先保留均值标签或对次要标签做上下错位偏移（连线仍指向真实 `yFromTop`，文本平滑避让）。

4. **G17 · 详细页（`DataPage`）年视图 `HeatGrid` 12 行标签挤压重叠**
   - **现象与定位**：`Controls/Charts/HeatGrid.cs:197-206` 对 `1月`–`12月` 每行按可用高度均分绘制 10px 纵轴标签；在年视图 12 行高密度网格下，可用 `cellHeight + Gap` 小于字体高度，导致标签互相粘连重叠。
   - **改进方案**：
     - 在 `HeatGrid` 中为 `cellHeight` 增设最小可读行高（结合 `FontSize + 4`）或按 `MinRowHeight` 动态计算画布所需高度并配合父级滚动；空间受限时降级为隔行/季度标注，或在年视图扩大 `HeatGrid` 容器高度阈值。

5. **G18 · 分类关联弹窗（`选择应用` / `选择站点`）搜索无效及列表脏数据**
   - **现象与定位**：① `CategoryWebSiteListPageViewModel.DoSearch`（第 175–179 行）采用 `WildcardHelper.IsMatch` 做通配符整串匹配，用户输入普通关键词（如 `"bilibili"`）未带 `*` 时直接匹配失败、列表未过滤；② `CategoryAppListPage.axaml:45-49` 仅靠 `KeyUp` 触发 `SearchCommand`（输入法组合/粘贴等场景易漏响应），且应用候选头部出现空白名称项及重复项（如多条同名软件或残留安装器条目）。
   - **改进方案**：
     - 将「选择站点」搜索默认改为不区分大小写的子串 `Contains`（仅当输入显式包含 `*`/`?` 时走 `WildcardHelper`）；
     - 「选择应用」弹窗改为对 `SearchInput` 做 `WhenPropertyChanged` + 短防抖实时过滤（与站点侧统一）；
     - 构建候选列表时过滤 `string.IsNullOrWhiteSpace(Description ?? Name)` 并按规范标识去重排序，消除空白/重复项。

6. **G19 · 侧边导航栏在设置页与 `Ctrl+K` 跳转后高亮态不同步**
   - **现象与定位**：`Views/MainWindow.axaml:286-292` 底部设置项设置了 `Uri="SettingsPage"`，而实际页面键与 `CommandParameter` 为 `"SettingPage"`；同时经底部齿轮进入设置页或经 `Ctrl+K` 跳入 `DetailPage` 后，`Navigation.SelectedItem` 仍停留在上一主导航项（如「分类」），造成“页面已切换但侧边栏紫色激活框指在旧页面”。
   - **改进方案**：
     - 统一 `MainWindow.axaml` 设置导航项 `Uri="SettingPage"`；
     - 在 `MainViewModel` 监听 `Uri` 变化联动导航高亮：若目标是 4 个主导航页则同步选中对应 `NavigationItemModel`，若为 `SettingPage` 则高亮设置入口，若为二级详情页/汇总页则清除主导航残留激活态（或高亮所属来源模块）。

### P2 · 体验打磨与细节一致性

7. **G20 · 概览页「自定义」日期胶囊点击未弹日历面板**

8. **G21 · 分类页「应用与网站」部分实体图标降级为蓝底占位且存在解码日志噪音**
   - **现象与定位**：同一应用在「概览 / 详细」页图标正常，而在「分类 → 应用与网站」卡片偶现蓝底占位，同时运行日志出现 `[Imager] 图片无法解码，已降级: WebFavicons/*.ico (NullReferenceException)`。
   - **改进方案**：
     - 核查「分类 → 应用与网站」卡片图标路径绑定与 `DecodeWidth` / `FallbackText` 传参是否与概览/榜单一致，确保站点未解码出 favicon 时统一回退域名首字母色块；
     - 优化 `Imager` 解码前校验（识别空头/损坏 ICO 流并缓存失败键），避免重复尝试解码报错并降低日志级别噪音。

9. **G22 · 设置页与 `Ctrl+K` 搜索浮层 3 处状态/文案细节**
   - **现象与定位**：
     1. 设置 → 数据「新建合并组」在勾选满 2 个成员后，底部红色提示 `"请至少选择 2 个成员"` 未即时隐藏（`SettingPageViewModel.SyncMergeSelectionState` 只更新了 `MergeEditorSelectedMembers`，未清空 `MergeEditorError` / `HasMergeEditorError`）；
     2. 设置 → 数据「启用 WebDAV 自动同步」`<toggle:Toggle>`（`SettingPage.axaml:348`）未显式绑定本地化 `OffText`/`OnText`，沿用了控件默认英文 `"Off"`；
     3. `Ctrl+K` 全局搜索底栏（`MainWindow.axaml:552-559`）键帽 `[↑↓]`/`[Esc]` 与文本 `SearchTipNav`（`↑↓ 选择`）/ `SearchTipClose`（`Esc 关闭`）字符重复。
   - **改进方案**：
     - `SyncMergeSelectionState` 中当已选成员 `>= 2` 且当前提示为成员数不足校验错误时自动清空 `MergeEditorError`；
     - 为设置页 WebDAV 开关及同类 `Toggle` 统一绑定资源字符串 `{DynamicResource ToggleOn}` / `{DynamicResource ToggleOff}`（或将 `Toggle` 默认文案对齐本地化资源）；
     - 清理 `SearchTipNav` / `SearchTipClose`（或底栏对应键帽）中的冗余前缀字符。
